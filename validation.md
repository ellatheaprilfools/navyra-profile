# Validation methodology and results

`navyra-profile`'s tier estimates are validated against synthetic traffic with known ground truth, generated by `synth.py`. Each synthetic prompt is labelled with its true tier at generation time. Cross-bucket (T3) labels are additionally validated against the real embedding model used by `analyse()`, so ground truth and the tool under test share one definition of semantic closeness.

## Method

Synthetic traffic was generated at five `template_share` values — 0.1, 0.2, 0.4, 0.6, 0.8 — at n=2,000 prompts each. Each dataset was passed to `analyse()`. Reported tier rates were converted from share-of-non-exact-traffic to share-of-total-traffic before comparison, matching the conversion used in the HTML/PDF report's waterfall chart. Reported rates were then compared against the known true rates.

## Results

| True templated share | T1 error | T2 error | T3 error |
|---|---|---|---|
| 10% | +0.1% | −1.2% | −0.2% |
| 20% | +0.2% | −1.9% | −0.2% |
| 40% | +0.3% | −1.8% | −0.3% |
| 60% | +0.3% | −0.6% | −0.4% |
| 80% | +0.3% | −0.5% | −0.3% |

Mean absolute error across the sweep: T1 0.2 points, T2 1.2 points, T3 0.3 points.

## Findings

T1 exact-repeat detection uses text matching, not model judgment. Error stays within 0.3 points across the full range tested.

T3 cross-bucket detection requires the tool to match semantically similar prompts of different lengths. Error stays within 0.4 points across the full range tested, despite this being a harder detection problem in principle than same-length matching.

T2 same-bucket detection underestimates the true rate at low template share and the error shrinks as template share increases: 1.2 points at 10% true templated share, 0.5 points at 80%. At low template share, genuine semantic matches are a small signal within a larger pool of unrelated traffic, reducing detection reliability proportionally. Absolute error remains small throughout the range. Detection accuracy is highest at higher repetition levels, which is where the tool has the most value.

## Limitations

Each sweep point uses a single random seed. Repeat runs at fixed configuration show variation of a few tenths of a percentage point between runs, a documented and expected source of noise. Averaging multiple seeds per sweep point would tighten these estimates. This was not done here, to keep sweep runtime bounded.

Ground truth for T2 and T3 depends on the synthetic generator's paraphrasing. Generation was iteratively refined and validated directly against the real embedding model rather than assumed correct. The generator's vocabulary is narrower than real-world traffic phrasing. These results are a lower bound on real-world accuracy, not an exact prediction of it.

T4 near-duplicate detection is excluded from this sweep. T4 is reported as a count, not a rate, throughout the tool, matching how it is presented in the HTML/PDF report.

## Reproducing these results

```bash
navyra-profile validate --n 2000 --shares 0.1,0.2,0.4,0.6,0.8
```

This regenerates synthetic traffic and re-runs the sweep against the installed build. Results will vary slightly from the table above due to the single-seed limitation noted above; the pattern (tight T1/T3, T2 tightening with template share) should hold.
